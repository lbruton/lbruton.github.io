Claude Code Guide

Hooks & Automation

Automatic context loading that fires without user action. MemFlow (mem0) memories and SessionFlow server start at session launch, safety guards before every tool use, and full context recovery after compaction.

Concept
Skills Are Manual. Hooks Are Automatic.

Skills like /prime require you to type a command. Hooks fire silently in the background at specific lifecycle events — session start, before tool use, after edits. The user never sees them run, but Claude receives the injected context.

This is the difference between "tell Claude what happened last session" (manual, via /prime) and "Claude already knows what happened last session" (automatic, via hooks). Hooks provide the baseline context layer; skills provide the deep dive when you need it.

SESSION LIFECYCLE SessionStart hooks fire → MemFlow memories injected silently (mem0-session-start.py) │ SessionFlow MCP server started (sessionflow-launcher.sh start) │ housekeeping tasks run (peon.sh) │ (Claude sees recent context without asking) ▼ User types /start → Quick resume (SessionFlow + MemFlow + git + issues) (or) User types /prime → Full boot (SessionFlow + MemFlow + indexes + health) │ (optional — for when you need the full picture) ▼ User edits a file │ PreToolUse hook fires → read-before-write.py blocks Edit if file unread │ duplication-checker.py guards re-implementations │ git-untracked-guard.py guards Bash on untracked files │ tasks-closing-gate.py blocks task close without log ▼ ... work continues ... │ PostToolUse hooks fire → docvault-lint.py validates DocVault edits │ post-edit-typecheck.py runs typechecks after edits │ agentlint-post-edit.py validates CLAUDE.md / SKILL.md ▼ Context window fills up → Claude compacts conversation │ SessionStart hook fires again → HEAVY MODE │ recovers handoff state + recent context ▼ Session continues with restored memory
SessionStart

Fires at session launch and after compaction. Three hooks run: mem0-session-start.py injects MemFlow memories silently, sessionflow-launcher.sh start ensures the SessionFlow MCP server is running, and peon.sh handles lightweight housekeeping. Two modes: lightweight (~5 memories) on startup, heavy (~10 memories + handoff state) after compact.

PreToolUse

Fires before a tool executes. Four active guards: read-before-write.py (core safety — blocks Edit/Write until file is read), duplication-checker.py (prevents redundant re-implementations), git-untracked-guard.py (guards Bash on untracked files), and tasks-closing-gate.py (prevents closing a task without proper logging).

PostToolUse

Fires after a tool completes. Three validators run: docvault-lint.py (validates DocVault note edits), post-edit-typecheck.py (runs type checks after file edits), and agentlint-post-edit.py (validates CLAUDE.md / AGENTS.md / SKILL.md compliance after edits).

Protocol
How Hooks Work

A hook is a command that Claude Code runs at a lifecycle event. It receives context on stdin and returns instructions on stdout as JSON.

Input (stdin)

Claude Code sends a JSON payload with event-specific fields:

// SessionStart — source tells you why it fired
{"source": "startup"}     // fresh session
{"source": "resume"}      // reconnected
{"source": "compact"}     // context was compacted

// PreToolUse — tool_input has the tool's parameters
{
  "tool_name": "Skill",
  "tool_input": {"skill": "spec", "args": "STAK-498"}
}

// UserPromptSubmit — the user's message
{"message": "fix the price scraper bug"}

Output (stdout)

The hook prints JSON to stdout. The key field is additionalContext — a string that gets silently injected into Claude's context.

// Inject context — Claude sees this but the user doesn't
{
  "additionalContext": "Recent context: you worked on STAK-498 yesterday..."
}

// SessionStart has a special wrapper format
{
  "hookSpecificOutput": {
    "hookEventName": "SessionStart",
    "additionalContext": "Recent mem0 context for StakTrakr..."
  }
}

// Empty output = hook ran but has nothing to inject
{}
Performance matters
Hooks block the event they're attached to. A slow SessionStart hook delays the entire session boot. Keep hooks under 4 seconds — use timeouts on all network calls, fail silently on errors, and return {} when there's nothing useful to inject.

Matcher field

The matcher filters when the hook fires:

EventMatcherEffect
SessionStart"" (empty)Fires on every session start and compaction
PreToolUse"" (empty)Fires before every tool call — each hook self-filters by tool name
PreToolUse"Edit"Fires only before Edit/Write calls (narrower alternative)
PostToolUse"" (empty)Fires after every tool completes — each hook self-filters by file type or tool
SessionStart Hooks
MemFlow Session Start

Three hooks fire at every session launch. mem0-session-start.py searches MemFlow (mem0) for recent project memories and injects them silently. sessionflow-launcher.sh start ensures the SessionFlow MCP server is running — replacing the retired session-rag-server.sh. peon.sh runs lightweight housekeeping tasks. Claude starts every session already knowing where you left off, without you typing anything.

Two modes

ModeWhenBehavior
Normal source: "startup" or "resume" Lightweight — 5 recent memories, last 7 days, brief format
Compact recovery source: "compact" Heavy — searches for pre-compact handoff state + 10 context memories, formatted with recovery header

The compact recovery mode is critical. When Claude's context window fills up and compacts, it loses the conversation history. This hook detects compaction and injects a heavier context block with a ## Context restored after compaction header, including any handoff state that was saved before the compact event.

Project detection

The hook detects which project you're in by reading the git root directory name and mapping it to a mem0 agent_id tag. This ensures you only get memories relevant to the current project, not cross-contamination from other work.

# Project mapping — git directory name → mem0 agent_id
PROJECT_MAP = {
    "StakTrakr": "staktrakr",
    "HexTrackr": "hextrackr",
    "MyMelo": "mymelo",
    "Forge": "forge",
    # ... add your projects
}

# The hook reads the git root:
#   git rev-parse --show-toplevel → /path/to/StakTrakr
#   basename → StakTrakr
#   PROJECT_MAP["StakTrakr"] → "staktrakr"
# Then searches mem0 with agent_id="staktrakr"

Source filtering

Not all mem0 memories are equal. The hook prefers memories from high-signal sources (session hooks, compaction hooks) over bulk-imported or migrated memories. If preferred-source memories exist, lower-quality ones are filtered out.

# High-signal sources — prefer these
PREFERRED_SOURCES = {"stop-hook", "pre-compact-hook", "post-tool-use-hook"}

# If any preferred-source memories exist, only show those
# Otherwise, fall back to showing everything

mem0-session-start.py 
#!/usr/bin/env python3
"""
mem0 SessionStart hook for Claude Code.

Two modes:
- startup/resume: Lightweight — 5 recent memories
- compact: Heavy — handoff state + 10 context memories

Reads MEM0_API_KEY from ~/.claude/.mcp.json.
Detects project from git root directory name.
"""

import json, os, re, subprocess, sys
from datetime import datetime, timedelta, timezone
from pathlib import Path
from urllib.request import Request, urlopen
from urllib.error import URLError, HTTPError

MEM0_API_URL = "https://api.mem0.ai/v1/memories/search/"
MCP_CONFIG = Path.home() / ".claude" / ".mcp.json"
MAX_NORMAL = 5
MAX_COMPACT = 10
LOOKBACK_DAYS = 7
EMPTY = json.dumps({})

# Map git directory names to mem0 agent_id tags
PROJECT_MAP = {
    "StakTrakr": "staktrakr",
    "HexTrackr": "hextrackr",
    "MyMelo": "mymelo",
    "Forge": "forge",
    # Add your projects here
}

PREFERRED_SOURCES = {"stop-hook", "pre-compact-hook", "post-tool-use-hook"}


def get_api_key():
    """Read MEM0_API_KEY from .mcp.json."""
    try:
        with open(MCP_CONFIG) as f:
            text = re.sub(r",\s*([}\]])", r"\1", f.read())
        config = json.loads(text)
        servers = config.get("mcpServers", config)
        return servers.get("mem0", {}).get("env", {}).get("MEM0_API_KEY")
    except Exception:
        return None


def get_project():
    """Detect project from git root."""
    try:
        r = subprocess.run(["git", "rev-parse", "--show-toplevel"],
                           capture_output=True, text=True, timeout=5)
        if r.returncode == 0:
            name = os.path.basename(r.stdout.strip())
            return name, PROJECT_MAP.get(name)
    except Exception:
        pass
    name = os.path.basename(os.getcwd())
    return name, PROJECT_MAP.get(name)


def search_mem0(api_key, query, limit, agent_id=None):
    """Search mem0 API, post-filter by project and date."""
    since = (datetime.now(timezone.utc)
             - timedelta(days=LOOKBACK_DAYS)).strftime("%Y-%m-%d")
    payload = {"query": query, "user_id": "lbruton",
               "limit": limit * 4 if agent_id else limit * 2}
    req = Request(MEM0_API_URL, data=json.dumps(payload).encode(),
                  headers={"Authorization": f"Token {api_key}",
                           "Content-Type": "application/json"},
                  method="POST")
    try:
        with urlopen(req, timeout=10) as resp:
            data = json.loads(resp.read().decode())
    except Exception:
        return []
    if not isinstance(data, list):
        data = data.get("results", [])

    filtered = []
    for mem in data:
        if mem.get("created_at", "")[:10] < since:
            continue
        if agent_id:
            proj = mem.get("metadata", {}).get("project", "").lower()
            if proj and proj != agent_id:
                continue
        filtered.append(mem)
    return filtered[:limit]


def filter_preferred(memories):
    preferred = [m for m in memories
                 if m.get("metadata", {}).get("source") in PREFERRED_SOURCES]
    return preferred if preferred else memories


def format_normal(memories, project_name):
    if not memories:
        return None
    memories = filter_preferred(memories)
    lines = [f"Recent mem0 context for {project_name} "
             f"(last {LOOKBACK_DAYS} days):"]
    for i, mem in enumerate(memories, 1):
        text = mem.get("memory", "").strip()
        if not text:
            continue
        if len(text) > 200:
            text = text[:197] + "..."
        date = mem.get("created_at", "")[:10]
        mtype = mem.get("metadata", {}).get("type", "")
        tag = f" ({mtype})" if mtype else ""
        lines.append(f"  {i}. [{date}]{tag} {text}")
    return "\n".join(lines) if len(lines) > 1 else None


def format_compact(handoff, context, project_name):
    sections = ["## Context restored after compaction\n"]
    context = filter_preferred(context)
    if handoff:
        sections.append("### Session state before compaction")
        for mem in handoff[:2]:
            text = mem.get("memory", "").strip()
            if text:
                sections.append(text[:500])
        sections.append("")
    if context:
        sections.append("### Recent project context")
        for i, mem in enumerate(context, 1):
            text = mem.get("memory", "").strip()
            if not text:
                continue
            if len(text) > 200:
                text = text[:197] + "..."
            date = mem.get("created_at", "")[:10]
            mtype = mem.get("metadata", {}).get("type", "")
            tag = f" ({mtype})" if mtype else ""
            sections.append(f"  {i}. [{date}]{tag} {text}")
    return "\n".join(sections) if len(sections) > 2 else None


def main():
    source = "startup"
    try:
        raw = sys.stdin.read()
        if raw:
            source = json.loads(raw).get("source", "startup")
    except Exception:
        pass

    api_key = get_api_key()
    project_name, agent_id = get_project()
    if not api_key or not agent_id:
        print(EMPTY)
        return

    if source == "compact":
        handoff = search_mem0(api_key,
            "pre-compact handoff session state", 3, agent_id)
        context = search_mem0(api_key,
            "recent decision pattern insight task", MAX_COMPACT, agent_id)
        result = format_compact(handoff, context, project_name)
    else:
        memories = search_mem0(api_key,
            "recent session decision in-progress pattern", MAX_NORMAL,
            agent_id)
        result = format_normal(memories, project_name)

    if not result:
        print(EMPTY)
        return
    print(json.dumps({"hookSpecificOutput": {
        "hookEventName": "SessionStart",
        "additionalContext": result}}))


if __name__ == "__main__":
    main()
PreToolUse Hooks
Safety Guards Before Every Tool Call

Four hooks fire before tools execute, each enforcing a different safety contract. They are all silent on success and return a blocking error message on violation. Together they catch the most common categories of accidental damage before any bytes are written.

read-before-write.py — the core guard

Blocks Edit or Write on any file that has not been read in the current session. This prevents Claude from overwriting a file based on stale assumptions about its contents. Every write requires a prior read — the hook tracks the read set in session state and rejects writes outside it.

# What happens on a blocked write:
{
  "decision": "block",
  "reason": "File has not been read this session. Read it first with the Read tool."
}

# What happens on a safe write (file was read earlier):
{}  # empty = proceed

duplication-checker.py

Before Claude writes a new function, class, or module, this hook searches the codebase for existing implementations of the same concept. It blocks the write if a near-duplicate already exists and surfaces the path to the existing code, preventing silent re-implementations that diverge over time.

git-untracked-guard.py

Guards Bash tool calls that operate on untracked files. When a shell command references a path that is not tracked by git (not staged, not committed), the hook warns Claude before the command runs. Catches accidental rm, mv, or overwrite operations on files that git cannot recover.

tasks-closing-gate.py

In spec-driven workflows, tasks must be logged via log-implementation before they can be checked off. This hook intercepts attempts to mark a task [x] and blocks the edit if the corresponding implementation log entry is missing — enforcing the spec gate without relying on Claude's memory.

HookTriggerWhat it blocks
read-before-write.pyEdit, WriteWrites to unread files
duplication-checker.pyEdit, WriteNear-duplicate implementations
git-untracked-guard.pyBashShell ops on untracked paths
tasks-closing-gate.pyEditTask close without implementation log
read-before-write.py (pattern) 
#!/usr/bin/env python3
"""
PreToolUse safety guard: block Edit/Write until file has been read.

Reads session state from a temp file that mem0-session-start.py
and other Read-tool observers update as files are accessed.
Silent on success (returns {}). Blocking on violation.
"""

import json, os, sys
from pathlib import Path

SESSION_READS = Path("/tmp/.claude_session_reads")
EMPTY = json.dumps({})


def get_read_set():
    try:
        return set(json.loads(SESSION_READS.read_text()))
    except Exception:
        return set()


def main():
    data = {}
    try:
        raw = sys.stdin.read()
        if raw:
            data = json.loads(raw)
    except Exception:
        print(EMPTY); return

    tool = data.get("tool_name", "")
    if tool not in ("Edit", "Write"):
        print(EMPTY); return

    file_path = (data.get("tool_input", {}).get("file_path")
                 or data.get("tool_input", {}).get("path", ""))
    if not file_path:
        print(EMPTY); return

    read_set = get_read_set()
    if os.path.abspath(file_path) not in read_set:
        print(json.dumps({
            "decision": "block",
            "reason": (f"File has not been read this session: {file_path}. "
                       "Read it first with the Read tool.")
        }))
    else:
        print(EMPTY)


if __name__ == "__main__":
    main()
PostToolUse Hooks
Validators After Every Edit

Three hooks fire after tool calls complete, catching issues immediately after they are introduced rather than at CI time or code review.

docvault-lint.py

After any edit to a file inside the DocVault Obsidian vault, this hook validates the note structure: required frontmatter fields, wikilink syntax, callout format, and tag conventions. Returns a structured lint report that Claude can act on immediately.

post-edit-typecheck.py

After any TypeScript or Python file edit, this hook runs the project's type checker (tsc --noEmit or pyright) scoped to the edited file. Type errors surface inline in the tool response rather than waiting for a CI run.

agentlint-post-edit.py

After any edit to CLAUDE.md, AGENTS.md, or SKILL.md files, this hook runs agentlinter against the modified file and injects the findings. Keeps instruction files compliant with the harness's formatting and structural rules as they evolve.

HookTriggerWhat it validates
docvault-lint.pyEdit inside DocVault pathFrontmatter, wikilinks, callouts, tags
post-edit-typecheck.pyEdit on .ts, .py filesType correctness, scoped to edited file
agentlint-post-edit.pyEdit on CLAUDE.md / SKILL.mdInstruction-file harness compliance
Architecture
The Layered Context Model

Hooks and skills work together as layers. Each layer adds more context, but only when needed. The session starts fast with just hook-injected memories, and the user can go deeper with manual skills.

LayerMechanismCostWhen
1. MemFlow baseline SessionStart injects ~5 recent MemFlow memories + starts SessionFlow server ~500 tokens, 2-3 seconds Every session, automatic
2. Safety guards PreToolUse blocks unsafe writes, duplicates, and unlogged task closes ~0 tokens (blocking only) Before each tool call, automatic
3. Post-edit validators PostToolUse runs typecheck, docvault-lint, agentlint after edits ~0-200 tokens (findings only) After each edit, automatic
4. /start quick resume SessionFlow + MemFlow + git + open issues in one command ~800 tokens, 5-10 seconds On demand, lightweight continuation
5. /prime deep load Reads vault, checks git, indexes, gathers issues, runs health scan ~2000 tokens, 15-30 seconds On demand, Monday mornings or context switches

Most sessions only need layers 1-3. You start Claude, the SessionStart hooks silently load yesterday's context and ensure SessionFlow is running, safety guards watch every tool call in the background, and you pick up where you left off. /start is for a quick same-day resume. /prime is for Monday mornings or after a long break.

Compaction recovery is the killer feature
Long sessions hit context limits and compact. Without the hook, Claude loses everything and you have to manually re-explain. With the hook, compaction fires a source: "compact" event, mem0-session-start.py searches MemFlow for the pre-compact handoff state, and injects it with a ## Context restored after compaction header. Claude picks up where it left off without the user even noticing the compaction happened.
Quick Start
Add Hooks to Your Setup

1. Save the hook scripts

mkdir -p ~/.claude/hooks

# SessionStart hooks
# mem0-session-start.py   — MemFlow memory injection
# sessionflow-launcher.sh — ensure SessionFlow MCP server is running
# peon.sh                 — lightweight housekeeping

# PreToolUse hooks
# read-before-write.py    — block writes to unread files
# duplication-checker.py  — catch redundant re-implementations
# git-untracked-guard.py  — guard Bash on untracked files
# tasks-closing-gate.py   — enforce implementation log before task close

# PostToolUse hooks
# docvault-lint.py        — validate DocVault note edits
# post-edit-typecheck.py  — typecheck after file edits
# agentlint-post-edit.py  — validate CLAUDE.md / SKILL.md compliance

chmod +x ~/.claude/hooks/*.py ~/.claude/hooks/*.sh

2. Get a MemFlow API key

Sign up at mem0.ai and add the key to your MCP config at ~/.claude/.mcp.json. The hooks read the key from the same config file your MCP server uses — single source of truth.

3. Register the hooks

Prompt for Claude: Register hooks in settings.json
Register the following hooks in my Claude Code ~/.claude/settings.json under the hooks key. Keep any existing settings intact.

SessionStart (empty matcher): mem0-session-start.py, sessionflow-launcher.sh start, peon.sh
PreToolUse (empty matcher): read-before-write.py, duplication-checker.py, git-untracked-guard.py, tasks-closing-gate.py
PostToolUse (empty matcher): docvault-lint.py, post-edit-typecheck.py, agentlint-post-edit.py

All scripts live in ~/.claude/hooks/. Use python3 for .py files and bash for .sh files.

4. Add your project mappings

Edit the PROJECT_MAP dictionary in mem0-session-start.py to map your git directory names to MemFlow agent_id tags. The hook only fires for mapped projects — unmapped directories get no context injection.

5. Verify it works

# Start a new Claude Code session in a mapped project
cd ~/MyProject
claude

# Claude should show injected MemFlow context in its first response
# You can also test hooks directly:
echo '{"source": "startup"}' | python3 ~/.claude/hooks/mem0-session-start.py
echo '{"source": "compact"}' | python3 ~/.claude/hooks/mem0-session-start.py
Minimum viable hook
You don't need mem0 to start. The simplest useful hook reads a local file and injects it: 
#!/usr/bin/env python3
import json
from pathlib import Path
notes = Path.home() / ".claude" / "session-notes.md"
if notes.exists():
    text = notes.read_text()[:1000]
    print(json.dumps({"hookSpecificOutput": {
        "hookEventName": "SessionStart",
        "additionalContext": text}}))
else:
    print("{}")
Write your notes to ~/.claude/session-notes.md at session end, and they'll be injected at the next session start. No API needed.
